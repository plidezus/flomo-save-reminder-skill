# flomo 保存提醒

## 核心定位

在 AI 对话中，发现那些可能值得留在 flomo 里的片段，整理成用户风格的 memo 草稿，并在写入前确认。

这不是自动记忆一切，也不是会议纪要工具。默认只提醒和起草，不擅自写入。保存动作要保留用户的主动选择。

## 文件结构

本 skill 只放稳定协议：

- `SKILL.md`：稳定协议，写判断、提醒、采样、写入边界。
- `../flomo-shared/SKILL.md`：共享 profile 的初始化、刷新和旧版本迁移协议。
- `../flomo-shared/profile.md`：共享 flomo profile，包含表达画像和用户明确确认过的偏好。

不要把具体用户的标签、口癖、私人内容写进 `SKILL.md`。这些只应该进入共享 profile 或运行时上下文。

## 启动检查

每次使用本 skill 且需要按用户风格生成 memo 草稿前，先读取 `../flomo-shared/profile.md`。

profile 状态：

- 文件不存在：`missing`。
- 文件为空、仍包含“待生成”、`profile_status: empty`，或 `updated_at` 为空：`empty`。
- 缺少 `updated_at: YYYY-MM-DD`，或日期无法解析：`invalid`。
- `updated_at` 距当前日期超过 30 天：`stale`。
- `profile_status: generated`，`updated_at` 距当前日期不超过 30 天，且没有模板占位：`fresh`。

根据状态处理：

- `fresh`：直接使用。
- `stale`：继续当前保存任务，不阻塞；任务结束后或用户同意时，用 `../flomo-shared/SKILL.md` 刷新。
- `missing` / `empty` / `invalid`：按 `../flomo-shared/SKILL.md` 初始化、修复或迁移；如果用户不同意读取样本，就使用保守草稿并明说未使用个性化画像。

不得在没有检查共享 profile 状态的情况下直接走 fallback。

fallback 只能作为降级路径，且必须满足至少一个条件：

- flomo MCP 不可用。
- memory 和 memo 采样都失败。
- 当前环境不能读取或写入共享 profile。
- 用户明确要求“先别读取我的笔记，直接给草稿”。

进入 fallback 时要明说：没有成功读取或生成共享 profile，所以这次使用保守草稿。

## 首次设置

如果 `profile.md` 中 `User Preferences / Save Reminder / reminder_mode` 为空，先问用户一个简短问题，不要先读取 flomo memo 样本：

```markdown
你希望 flomo 保存提醒怎么工作？

1. 只在我说“保存/记一下”时使用
2. 我让你扫描当前对话时，帮我挑值得保存的内容
3. 本轮对话里，看到特别值得留的内容可以轻提醒
```

根据用户选择写入 `profile.md` 的 `User Preferences / Save Reminder`：

- `explicit_only`：只在用户明确说保存、记一下、整理成 flomo 时使用。
- `scan_on_request`：用户要求扫描当前对话时，集中判断哪些内容值得保存。
- `session_light`：仅本轮或用户授权的会话中，允许低频轻提醒。

默认推荐 `scan_on_request`。不要默认开启全局主动提醒。

## 五个保存入口

用以下五个入口判断“是否值得提醒保存”。它们不是标签，也不要直接写进 memo。

1. **想到什么**
   - 灵感、问题、判断、观点、假设、类比。
   - 触发：用户把一个想法说清楚，未来可能继续展开。

2. **感受到什么**
   - 情绪、内心感受、自我觉察、关系中的体感。
   - 触发：用户不只是发泄，而是形成了对自己或处境的理解。

3. **经历了什么**
   - 日记、生活片段、关系现场、和别人交流后的片段。
   - 触发：有具体场景、人物或时间感，未来回看会有意义。

4. **读到/听到什么**
   - 书、文章、播客、视频、课程、外部信息。
   - 触发：用户不是只转述，而是把外部内容转成了自己的理解。

5. **做事中学到什么**
   - 工作、产品、项目、会议、创作、复盘、决策。
   - 触发：形成经验、判断、下一步、原则或可复用流程。

## 不提醒场景

不要提醒保存：

- 普通事实问答。
- 纯临时任务或查询结果。
- AI 单方面总结，但用户没有产生新想法或新表达。
- 情绪还在流动中，尚未形成用户愿意留下的表达。
- 只有链接、摘录或信息转述，没有用户自己的反应。
- 同一话题短时间内已经提醒过。
- 内容涉及敏感或第三方隐私，且用户没有明确保存意图。
- 保存后只会增加噪音，未来很难复用。

## 触发前自检

提醒前问三个问题：

1. 未来用户是否可能想找回这句话、这个感受或这个问题？
2. 这是用户自己的表达，而不是 AI 的发挥吗？
3. 存下来会增加回看的可能性，而不是增加噪音吗？

至少两个答案为“是”，才提醒。

## 上下文来源

优先级如下：

1. **用户明确指令**
   - 用户指定标签、格式、保存目标时，优先遵守。

2. **共享 profile 的 Expression Profile**
   - 读取 `../flomo-shared/profile.md` 的 `Expression Profile`。
   - 主要用于 memo 格式、标签习惯、长度、保存价值判断和草稿风格。
   - 如果存在且未过期，优先读取。

3. **flomo MCP memory 接口**
   - 如果有 `memory_user`：用于理解用户相对稳定的身份、偏好和边界。
   - 如果有 `memory_context`：用于理解用户近期关注、项目和语境。
   - 这两个接口是“上下文”，不是“写作风格画像”。不要只凭 memory 直接决定标签或格式。

4. **flomo memo 采样**
   - 用于学习真实 memo 风格和标签习惯。
   - 用于补足 memory 中没有的具体写法。

5. **冷启动默认规则**
   - 如果没有 memory，也无法读 memo，则使用保守短 memo 草稿，不强行打标签。

## 共享 profile

`../flomo-shared/profile.md` 是 flomo 相关 skills 共用的 profile，由 `../flomo-shared/SKILL.md` 负责初始化、刷新和迁移。

本 skill 可以读取：

- `Expression Profile`：用于格式、标签、长度、草稿风格和保存价值判断。
- `User Preferences / Save Reminder`：用于保存提醒主动性和确认边界。

本 skill 不负责从样本生成画像。需要初始化、刷新或迁移时，交给 `flomo-shared` 的协议。

`Expression Profile` 可以从 memo 样本刷新；`User Preferences` 只能由用户明确确认后修改。不要根据 memo 样本推断用户希望更主动、允许自动保存或愿意开启定时。

## MCP memory 处理规则

如果 flomo MCP 提供 memory 接口：

- 优先轻量读取 `memory_user`，获得稳定偏好、身份、禁区和长期关注。
- 只在需要理解当前话题时读取 `memory_context`，不要每次提醒都重查。
- memory 只负责“别误解用户”，不负责“替用户写成 memo”。
- 标签、格式、长度、语气仍以共享 profile 的 Expression Profile 和真实 memo 样本为准。

如果 flomo MCP 没有 memory 接口，或接口鉴权失败、超时、返回为空：

- 不阻塞保存提醒。
- 先读共享 profile。
- profile 缺失或过期时，按 `flomo-shared` 协议处理。
- profile 和 memo 都无法读取时，使用保守短草稿，并明确说明没有读取到用户样本。
- 不要假装已经读取 memory，也不要把通用推断写成用户画像。

## 标签策略

标签不是内容分类，不由“五个保存入口”直接决定。

优先级：

1. 用户明确指定的标签。
2. 相似 memo 中反复出现的标签。
3. 共享 profile 中记录的高置信常用标签。
4. 目标 memo 内容中自然出现且用户历史中存在的标签。
5. 置信度不足时，少打标签或不打标签。

禁止为了完整而创造新标签。不要在通用协议中写死某个用户的标签。

## memo 草稿标准

好的 memo 草稿应该：

- 短。
- 具体。
- 可搜索。
- 有用户自己的声音。
- 保留关键原话。
- 以后回看仍能理解当时为什么要记。
- 不替用户过度拔高。
- 不把 AI 推断写成用户确定判断。

避免：

- 泛泛总结。
- 鸡汤化。
- 过度心理分析。
- 自动加意义。
- 为了完整而写太长。
- “这说明你很重视……”这类空泛句式。
- 写得像会议纪要或知识库条目。

没有样本时，使用保守默认格式：

```markdown
- 一句话写下值得保存的内容。
- 必要时补充背景、来源或下一步。
```

## 提醒话术

默认用低打扰提醒：

```markdown
这句像是可以留在 flomo 里：

「……」

我可以整理成一条 memo：

……

要保存吗？
```

更轻的版本：

```markdown
这句挺像一条 flomo：

「……」

要我帮你记一下吗？
```

如果用户明确说“记一下”或“保存到 flomo”，不要再解释判断理由，直接整理并写入。

## 写入规则

默认不写入。只有在以下情况写入：

- 用户明确确认“保存”“可以”“记一下”“存到 flomo”。
- 用户已提前授权当前类型内容自动保存。
- 当前任务本身就是保存到 flomo。

写入前：

- 先读取 flomo 格式规范工具，例如 `get_format_guide`。
- 标签直接写在正文里。
- 避免 flomo 不支持的 Markdown：标题、引用、代码块、表格、复杂链接语法等。
- 避免保存未确认的推断。
- 对敏感或第三方隐私内容保持克制。

写入后：

- 返回 memo id。
- 不要额外扩写。

## 自动保存边界

自动保存必须是例外，不是默认。

可以自动保存：

- 用户明确授权的内容类型。
- 用户直接说“以后这类都自动保存”。
- 明确的用户偏好、产品/工作决策或反复出现的个人原则。

不要自动保存：

- 敏感第三方信息。
- 未确认推断。
- 临时情绪。
- 普通问答。
- 低价值摘要。

## 失败处理

- 如果 flomo MCP memory 接口不可用：跳过 memory，尝试 memo 采样。
- 如果共享 profile 缺失、为空或过期：按 `flomo-shared` 协议初始化或刷新；只有用户拒绝、采样失败或写回失败后，才可以降级。
- 如果 memo 采样不可用：说明无法读取样本，给出保守草稿，不伪装已生成用户画像。
- 如果写入工具不可用：给出草稿，并说明没有写入。
- 如果格式不确定：先用保守短 memo，不发明复杂结构。
- 如果误触发：用户没有回应就继续，不要追问。
